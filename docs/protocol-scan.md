# Протокол сетевого сканирования KX-MB2020

Восстановлен по двум захватам штатной программы (Multi-Function Station 1.18, драйвер KX-MB2000 1.13) и проверен прототипом `proto/windows/mfpp_scan.ps1`.

Примеры адресов ниже вымышленные: ПК `192.168.1.10` (имя `MYPC`, MAC `00:11:22:33:44:55`), МФУ `192.168.1.50`.

## Участники и порты

| Направление | Протокол | Порт | Назначение |
|---|---|---|---|
| ПК → МФУ | UDP | 3892 | команды MFPP (с нового эфемерного порта на каждую команду) |
| МФУ → ПК | UDP | с 655xx на порт отправителя | ответы MFPP (порт-источник убывающий счётчик: 65523, 65522, …) |
| МФУ → ПК | TCP | 3892 (ПК — сервер) | передача картинки по LPR/LPD |
| ПК → МФУ | UDP | 161 | SNMP v1 (`public`), опрос статуса, приватная ветка 1.3.6.1.4.1.258.75… |

Важно: на ПК должен быть открыт **входящий TCP 3892**. UDP-ответ МФУ приходит не с порта 3892, поэтому брандмауэр Windows его не пропускает как ответ — нужно правило на входящий UDP от МФУ либо перехват через Npcap.

## Формат UDP-пакета MFPP

```
смещ  размер  поле
0     12      "MFPP0200ML01" (ASCII)
12    2       seq, uint16 LE (растёт от команды к команде; ответ повторяет seq запроса)
14    1       класс: 0x31 (обнаружение) / 0x32 (сканирование)
15    1       код
16    4       длина тела, uint32 LE
20    N       тело
```

## Коды

| Класс/код | Направление | Длина | Тело |
|---|---|---|---|
| `31 03` | ПК → МФУ | 48 | объявление ПК (см. ниже); МФУ отвечает тем же пакетом с кодом `31 C4` |
| `31 05` | ПК → МФУ | 48 | то же тело, без ответа |
| `31 C4` | МФУ → ПК | 48 | эхо объявления |
| `32 10` | ПК → МФУ | 20 | опрос/готовность, тело пустое (UDP-ответа нет) |
| `32 41` | ПК → МФУ | 148 | параметры скана, тело 0x80 байт |
| `32 43` | МФУ → ПК | 28 | ID задания, тело 8 байт |
| `32 62` | ПК → МФУ | 28 | подтверждение: то же тело, что в `32 43` |

### Тело объявления (`31 03`/`31 05`/`31 C4`), 28 байт

```
0   4   IPv4 ПК (c0 a8 01 0a)
4   16  имя ПК, ASCII, заглавные, добито нулями ("MYPC")
20  6   MAC ПК
26  2   00 0f
```

### Тело параметров (`32 41`), 0x80 байт, uint32 LE

```
0x00  3      режим (наблюдалось 3/3/3 для цветного скана; значения других режимов не исследованы)
0x04  3
0x08  3
0x0C  300    dpi X
0x10  300    dpi Y
0x14  0      (лево?)
0x18  0      (верх?)
0x1C  2480   ширина области, пикс
0x20  3508   высота области, пикс
...   0
```

### ID задания (`32 43`/`32 62`), 8 байт

`4 последних байта MAC МФУ` + 4 ASCII-цифры номера задания (`"0001"`, `"0002"`, … — счётчик МФУ).

## Последовательность

```
ПК  -> МФУ  UDP 31 03 (объявление)          МФУ -> ПК 31 C4
ПК  -> МФУ  UDP 31 05
ПК  -> МФУ  UDP 32 10  ×3
ПК  -> МФУ  UDP 32 41 (параметры)           МФУ -> ПК 32 43 (ID)
ПК  -> МФУ  UDP 32 62 (ID)
МФУ -> ПК   TCP connect :3892  (через ~10 мс)
            LPR: "\x02lp\n" → \0
                 "\x02<len> cfA<NNN><HOST>\n" → \0, control-файл, \0 → \0
                 "\x03<len> dfA<NNN><HOST>\n" → \0, data-файл, \0 → \0
МФУ -> ПК   второе короткое TCP-соединение: control-файл cfA<NNN+1> без data (маркер конца)
ПК  -> МФУ  UDP 32 10  ×3
```

`<HOST>` — имя МФУ вида `MB2020RU_xxxxxx` (хвост MAC). Control-файл содержит строки `H<host>`, `N<NNN>_<nnn>.DAT` и расширенные бинарные поля `0x80 …` с MAC и IP МФУ и копией UDP-заголовка задания.

## Data-файл скана

```
0x00  u32 режим (3)        0x04 u32 (3)       0x08 u32 (3)
0x0C  u32 dpi X (300)      0x10 u32 dpi Y (300)
0x1C  u32 ширина (2480)    0x20 u32 запрошенная высота (3508)
0x54  u32 0xC6 (?)         0x60 u32 0x0003A200 (?)   0x78 u32 2 (?)
0x80  пиксели: RGB 8 бит, R-G-B, построчно, 3 байта × ширина, без заголовков строк
```

A4/300 dpi/цвет: 128 + 7440 × 3504 = 26 069 888 байт. Фактическая высота (3504) на 4 строки меньше запрошенной. Передача ~36 с.

## Открытые вопросы

- Значения режима для ч/б и оттенков серого, другие разрешения, область скана, сканирование из автоподатчика.
- Значение полей 0x54/0x60/0x78 заголовка.
- Назначение `31 05` и UDP-ответов на `32 10` (их нет — статус, видимо, по SNMP).
